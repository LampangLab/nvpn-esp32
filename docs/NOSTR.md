# ชั้น Nostr: สั่งและดูบอร์ดจากหน้าเว็บผ่าน relay สาธารณะ

ใช้เมื่ออยากให้ "ใครก็ได้ที่มีหน้าเว็บ" ดู/สั่งบอร์ดได้ โดยไม่ต้องลงแอปหรือเปิด PC ไม่ต้องมีเซิร์ฟเวอร์ที่ต้องจ่ายเงิน
(เป็นอีกทางหนึ่งแยกจาก VPN: VPN ใช้กับกลุ่มปิดที่ลงแอป nostr-vpn ส่วนชั้นนี้ใช้ข้อความ Nostr ผ่าน relay)

## หลักการ
- บอร์ดต่อออกไปหา relay แบบ `wss://` (ขาออกอย่างเดียว) จึงใช้ได้กับ Wi-Fi/CGNAT/router ที่ตั้งค่าไม่ได้
- บอร์ด → relay: สถานะ kind **21080** (ephemeral) ทุก 30 วินาทีและเมื่อสถานะเปลี่ยน; หน้าเว็บขอสถานะทันทีด้วยคำสั่ง `status` ตอนเชื่อมต่อ (relay ไม่เก็บอีเวนต์ ephemeral จึงไม่มี "สถานะล่าสุด" ให้ดึงย้อนหลังเมื่อบอร์ดดับ)
- หน้าเว็บ → relay → บอร์ด: คำสั่ง kind **21078** (ephemeral, tag `p`=กุญแจบอร์ด) เนื้อหา `{"cmd":"led","arg":1}`
- บอร์ด → หน้าเว็บ: คำตอบ kind **21079** (tag `p`=ผู้สั่ง, `e`=id คำสั่ง)
- ทุกอีเวนต์เซ็นด้วย BIP-340; บอร์ดตรวจ id+ลายเซ็น, กัน replay (เวลาห่างเกิน 90 วินาทีทิ้ง, id ซ้ำทิ้ง)
- สิทธิ์: `ping` และ `status` ใครก็ส่งได้; คำสั่งที่เปลี่ยนค่า (เช่น `led`) ต้องเป็นกุญแจใน `CONTROLLERS[]` (หรือตั้ง `ALLOW_ANYONE=true`)

## ตั้งค่า
1. ติดตั้งไลบรารี `nvpn-esp32` (zip เดิม), "WebSockets" (Markus Sattler), "ArduinoJson" v7
2. เปิด `NostrBoard/NostrBoard.ino` ใส่ SSID/รหัสผ่าน (relay เริ่มต้น `nos.lol`) แล้วอัปโหลด
3. Serial จะพิมพ์ `board key: npub1...` ให้ก๊อปไปใส่ในหน้าเว็บ
4. เปิด `web/index.html` (ดับเบิลคลิกจากเครื่อง หรืออัปโหลดขึ้นโฮสต์ฟรีเช่น GitHub Pages) ใส่ relay เดียวกับบอร์ดและ npub ของบอร์ด กด "เชื่อมต่อ"
5. หน้าเว็บแสดง "กุญแจของฉัน" (npub) เอาไปใส่ `CONTROLLERS[]` ในสเก็ตช์ แล้วอัปโหลดใหม่ จึงจะสั่ง LED ได้

## ข้อกำหนด Nostr ที่เกี่ยวข้อง (ตรวจจากข้อความ NIP-01 และ NIP-78)
- **NIP-01:** ชนิด 20000–29999 เป็น ephemeral (relay "ไม่คาดว่าจะเก็บ"), 30000–39999 เป็น addressable; เป็นเพียงข้อตกลง relay แต่ละเจ้าทำต่างได้; relay ปฏิเสธด้วยคำนำหน้า `rate-limited`, `blocked`, `restricted`, `invalid` (เช่น เวลาในอีเวนต์เพี้ยนจากเวลาจริงมาก), `mute` (ephemeral ที่ไม่มีใครฟัง) — บอร์ดพิมพ์ข้อความ `OK`/`NOTICE` เหล่านี้ลง Serial
- **NIP-78 (kind 30078):** เป็น "ข้อมูลส่วนตัวของแอป" relay ควรบังคับ NIP-42 AUTH และส่งให้เจ้าของเท่านั้น เราจึง **ไม่ใช้** 30078 กับสถานะสาธารณะ
- ชนิด 21078/21079/21080 เป็นเลขที่เราเลือกเอง ยังไม่ได้ตรวจกับทะเบียน kind ทางการ ก่อนเผยแพร่วงกว้างควรตรวจ/เสนอเลขที่ไม่ชนผ่านกระบวนการ NIP
- ต้องตั้งเวลาบอร์ดให้ถูก (NTP) ไม่งั้น relay อาจปฏิเสธอีเวนต์ว่าเวลาเพี้ยน

## ข้อควรรู้ด้านความปลอดภัย
- เนื้อหา **เซ็นแต่ไม่ได้เข้ารหัส** relay และคนอื่นอ่านสถานะ/คำสั่งได้ ห้ามใส่ความลับ
- ตอนนี้บอร์ดไม่ตรวจใบรับรอง TLS ของ relay (ไลบรารี WebSockets ไม่ตรวจถ้าไม่ใส่ CA) คนกลางหน่วงหรือบล็อกได้ แต่ปลอมคำสั่งไม่ได้เพราะต้องมีลายเซ็นของกุญแจที่อนุญาต
- relay สาธารณะอาจจำกัดอัตรา/ปิดเขียนฟรีเมื่อไหร่ก็ได้ ถ้าใช้จริงจังควรเลือก relay สำรองหรือรันเอง
- กุญแจส่วนตัวของผู้สั่งอยู่ใน localStorage ของเบราว์เซอร์ ใครเข้าถึงเบราว์เซอร์นั้นสั่งบอร์ดได้

## สถานะการทดสอบ
ผ่านบนเครื่องพัฒนา (ไม่มีบอร์ดจริง ไม่มี relay จริง):
- `test/nostr/cross.mjs`: โค้ด C สร้าง/ตรวจอีเวนต์ ↔ nostr-tools 54/54 (รวมอักขระพิเศษ ไทย อีโมจิ และตรวจจับการแก้เนื้อหา)
- `test/nostr/harness_test.mjs`: คอมไพล์โค้ดสเก็ตช์จริงบนเครื่องด้วยตัวจำลอง Arduino (ArduinoJson ตัวจริง) ป้อนอีเวนต์จาก nostr-tools: 10/10
- `test/nostr/ui.mjs`: เบราว์เซอร์จริง (Chromium) + relay จำลอง + ตัวจำลองบอร์ดที่เซ็น/ตรวจด้วยโค้ด C: 10/10

**ยังไม่ได้ทดสอบ:** บนบอร์ดจริง, TLS/WebSocket จริงกับ relay จริง (nos.lol ฯลฯ), หน่วยความจำบนบอร์ด, การทำงานของ relay แต่ละเจ้ากับ kind 21078/21079 (ephemeral) (21078/21079/21080 เป็นชนิดที่ไม่ได้ลงทะเบียน), นาฬิกา NTP บนบอร์ดจริง, การโฮสต์หน้าเว็บบน GitHub Pages
